DAWN OF DECAY — THE SPEC RECONNAISSANCE

The eight specs that hold no authored rune, derived from the code so that forty runes can be written against what the game actually does. This is a REPORT. Nothing here was authored, changed, retired or retuned — no rune was proposed, sketched, named or reserved; no card, ability, talent, constant or magnitude moved. Every section is written to be read ALONE, while that spec's five are being drafted, so the shared arithmetic is repeated rather than cross-referenced.

WHY THIS DOCUMENT EXISTS. Batch EZ authored five Occultist runes from recollection and four of its premises described bases that do not exist — Hex of Ruin already struck three, Wrath of the Old Gods already marked two, Shieldwall covers no ally, and “15% narrower a press” had been SS_SEQ_TAPER since CS. Every one was “the card already does that.” Batch FD then found the two cards named in a tag ruling were not in the population at all. Authoring from recollection cost four batches of repair on one spec's five runes. So the §2 half of every section below — what a rune must NOT be written to do, because it is already true — is the half this page is for.

ONE INSTRUMENT FAULT, FOUND AND FIXED WHILE THIS WAS BEING WRITTEN, AND RECORDED BECAUSE IT NEARLY BECAME A HEADLINE. The read-site sweep masked string literals before matching, the ordinary way to stop a sweep matching its own name inside a comment. Half this codebase's field reads are string-keyed — _max_hero_rank("frigid_ranks", "rune_frigid_ranks"), cfg.get("rune_opening_volley", 0) — so the masked sweep reported five idle rune_* fields as having ZERO read sites, four of them the Cryomancer's. That reads as a rune written against these would install and do nothing, and it is false: all five are read. The stripper now cuts only the comment, tracking quotes so a # inside "#e05050" does not truncate the line, and the two versions were run against the same population as each other's control — 5 dead against 0 dead. The correct number of dead rune fields is zero.

THE TWO CONDITION SHAPES, AND THE ARITHMETIC EVERY SECTION REPEATS

A rune's optional clause comes through one of two predicates, and both read the hero's drafted-and-equipped cards only — Runes.drafted_names(member) reads bm_equipped, falling back to bm_abilities. The protected core is NOT counted, which is the ES §4 ruling: a core kit alone met a 2+ BREAK threshold for ten of twelve specs, so the conditions moved to drafted-only counting.

  • THRESHOLD — Classes.primary_tag_count(drafted, tag) * 2 >= drafted.size(). At least HALF the drafted cards carry the tag as their PRIMARY. A secondary tag counts for nothing.
  • BREADTH — Classes.primary_tag_peak(drafted) * 3 <= drafted.size(). No single primary tag exceeds a third of the bar. This is a BOUND ON THE PEAK, not a count of tags touched.
  • Both refuse an empty list (FA §1), and the guard is in the predicates themselves so the hero sheet and the loadout panel cannot draw a tick on an empty bar.

The bar size n is the number of EARNED cards carried, and it moves with the ladder: ABILITY_SLOTS_BY_BOSS is [7, 8, 9, 10] and ability_slots_used = core_slots(spec) + equipped, so a 3-slot spec carries 4 to 7 and the Holy Cleric, at core_slots 4, carries 3 to 6. A condition can therefore be satisfiable at one rung of the ladder and not another, and two of the eight below have exactly that shape.

AND ONE FACT THAT APPLIES TO ALL TWELVE SPECS: BREAK CANNOT CARRY A THRESHOLD, ANYWHERE. Of the 227 tagged cards in the game, 0 carry BREAK as their PRIMARY tag and 99 carry it as a secondary. FD made BREAK secondary-only deliberately; the consequence nobody has written down is that primary_tag_count(drafted, "BREAK") is always zero, so a THRESHOLD rune gated on BREAK is inert for every hero in every build. The same is true of any tag with too few primaries in a given spec's pool, and each section below states which.

THE INVARIANT, AND IT HOLDS FOR ALL FOUR SETS: each authored spec got EXACTLY ONE THRESHOLD, EXACTLY ONE BREADTH and EXACTLY ONE TRADEOFF, with the rest bare. Verified across all four sets. That is 4 × 3 = 12 runes carrying a secondary and 9 bare, which is exactly the 21. The THRESHOLD and BREADTH are always on a PASSIVE; the TRADEOFF is on a STAT twice (Warden, Beastmaster) and on an ABILITY twice (Occultist, Sharpshooter). The Beastmaster is the only set of six; the extra rune is a bare PASSIVE. This is a description of what was done, not a rule that binds the eight.

Which tags a live rune gates on. Only THRESHOLD names a tag; BREADTH is tag-agnostic and four runes carry it. Gated more than once: DEFENSE (×2). Gated once: DEBUFF, MARK. Gated by NO live rune: BREAK, RESOURCE, OFFENSE, TEMPO — and of those, BREAK can never be gated at all, for the reason given above.

Prices and requirements. All 21 live runes are priced at 100g — the price is not yet a lever. 3 of 21 carry requires_ability: Open Wound → Shadowrend, Split Shield → Shieldwall, Ambush → Called Volley. None carries a lane — ES §5 severed the lane rule, and check_ez asserts a live rune carrying one is the severed rule coming back.

The retired 66 are not gone. Their payload fields are still declared on BattleUnit and still read in battle.gd — 58 idle rune_* fields, every one of them wired. Each section below lists the ones that belong to that spec, because they are what an author can reach with no new code.

The engine — Blood Frenzy (passive_id = "bloodrage")

The mechanic as the code states it: Blood Frenzy: +2% damage for every 5% of health missing. Half the highest bonus reached in a battle is kept as a floor for the rest of it.

What a rune must NOT be authored to do

Because it is already true:

  • The floor already survives a heal. frenzy_bonus() is called from take_hit and take_tick_damage for the side effect alone, so a dive that is healed away before his next swing has already banked half of it. A rune that “keeps what he reached” is Scar Tissue and Unslaked.
  • Spending Rage already feeds the passive. CZ's second term means every Rage cost in his kit is already a Frenzy step. A rune paying Frenzy for spending Rage pays twice for one act.
  • Unslaked already raises the ratchet rate to 100% for four turns (unit.gd:2708), and it uses maxf so it can never lower a Scar Tissue Berserker.
  • Boil Over already returns only the floor for two turns (unit.gd:2723), written as a RETURN rather than a write, so nothing can permanently lower the floor.
  • Four of his seventeen earnable cards already cost no resource and three of those (Blood Offering, Blood Price, Reckless Abandon) convert health or Rage into the passive directly.

Because it is structurally unavailable:

  • He has exactly ONE idle rune field — rune_bloodrage_step_bonus, the step-size term — against the Devout's seven and the Occultist's eight. Anything else a Berserker rune wants to do needs new code in battle.gd.
  • The band cannot be deepened from data. FRENZY_MAX_STEPS is a const with no bonus term beside it, so a rune can only make him reach +40% sooner, never further. That was CZ's explicit design decision, not an oversight.
  • The payout is one line. Everything Blood Frenzy pays goes through battle.gd:9315; there is no per-ability hook, so a rune cannot make one card read the meter differently.

What a rune must NOT be authored to do

Because it is already true:

  • The breadth term already counts statuses from ANY source, including his allies'. PROTECTED_CORES' own why for this spec says so. A rune that “lets your allies' debuffs count” is the passive.
  • Choking Smoke already applies TWO different afflictions to every enemy (blind and burn), which is the most direct breadth-builder in the kit.
  • Venom Coating already adds poison to every strike for four turns; Snare Line already lands a line on the whole enemy team; Explosive Shot is already AoE poison.
  • Harvest and Cull already read the affliction count — Cull purges and converts, Harvest redistributes. The “spend the board” lever exists twice.
  • Deadfall already duplicates Snare Trap and has since BD; the talent audit found it and it is on the open queue. A rune in that space lands on a known collision.

Because it is structurally unavailable:

  • Both halves of Trapper are bare literals. The +8% step (battle.gd:9227) and the 25% barb chance (battle.gd:10964) carry no bonus field, no talent term, nothing. A rune deepening either needs code. Compare Blood Frenzy, whose step has two.
  • Force of Nature REPLACES the passive rather than adding to it. The branch is if force_of_nature != null: ... elif passive_id == "trapper": ..., so a Survivalist holding that capstone stops reading his own passive's term entirely. Any rune written against the 8% is silently worth nothing to him.
  • The ceiling is a design constant, not a dial. Breadth is bounded by the size of DEBUFF_IDS; there is no cap term to raise.
  • His six idle rune fields all belong to the Venom, Snares and Guerilla node terms (rune_potent_ranks, rune_coated_blades, rune_wire_ranks, rune_cruel_ranks, rune_scavenger_ranks, rune_vulture) — every one deepens a NODE, none touches the passive.
