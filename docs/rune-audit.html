DAWN OF DECAY — THE RUNE AUDIT

All 65 authored runes, sorted by what each one actually modifies — derived from the READ SITE in scripts/, never from the rune's description and never from its lane field. This is a REPORT. Nothing here was fixed — no rune was re-keyed, re-authored, retuned or retired, no lane field was removed, no magnitude moved and no description was edited. The question it answers is one the designer asked before starting: how much of the rune layer does the new charter remove?

THE CHARTER THIS PAGE MEASURES AGAINST IS RULED AND NOT YET IMPLEMENTED. "Runes are disconnected from talents. They are run-specific items only. Their purpose is to modify stats and resources, and to modify the mechanics and values of core abilities, draft abilities, and passives." Nothing in the code or the documents is wrong against the rule the runes were actually written to, which is the opposite rule: master.html and docs/design-notes.md both state it as current — one rune per talent lane plus one splash, each lane rune writing that lane's own counters, because "the same rune is worth more to a hero whose points went elsewhere." scripts/runes.gd's own header says the same thing in one line: "talent counter fields STACK with the talent — intended." So no document is corrected on this page. The gap is between the code and the NEW rule, and every number below sizes that gap rather than reporting a defect.

§1 — THE ANSWER, IN ONE TABLE

§2 — DID THE TALENT REBUILD BREAK ANY OF THEM?

check_dp §4 asserts that every rune stat field has a live read site — 116 fields, 0 dead, confirmed live on this tree. That is a different question. A live read site proves the field is read. It does not prove the rune still buys what it was authored to buy: a node re-authored from "Rime lasts 2 turns longer" to "Blizzard costs 10 less Mana" leaves the counter alive and the rune buying something else.

SO ALL 84 FIELDS WERE COMPARED AT THEIR READ SITE AND AT THEIR ENCLOSING GUARD CHAIN AGAINST DN~1. FIVE MOVED. Three are unrelated to the rebuild and two are it.

THE ONE THAT IS NOT ON ANY RECORD — THE RUNE OF THE STANDING VOW

DO cut Sacred Resolve's banner out of Healing Pulse's trigger, for a good and stated reason: Sacred Resolve became a DRAFT card at DO, and "a node reading its banner would be a bet; Consecrated Ground is PROTECTED CORE." DO reported the node cut in its own §3 table, in the row dv_pulse | "or Sacred Resolve" | none | same condition, one site.

What is on no record anywhere is that a 100g rune rides that counter. The Rune of the Standing Vow writes blessed_barrier_ranks, devoutness_ranks and pulse_ranks; its third clause has fired under strictly fewer conditions since DO. A grep for "Standing Vow" and for pulse_ranks across every batch report, docs/state.md and the changelog returns zero hits.

IT IS A QUIET WEAKENING RATHER THAN A MIS-SALE, AND THE DISTINCTION IS WORTH KEEPING. The rune's description reads "holy ground mends 2% each turn" and is byte-identical before and after DO — it never sold the Sacred Resolve half. So the code moved TOWARD the card: the rune was over-delivering against its own text and now delivers exactly what it says. Nobody was mis-sold; the rune simply got worse than it was, and no instrument could see it.

AND THE SHARPEST LESSON IN THE BATCH IS oc_spread

Its node dictionary changed by DESCRIPTION ONLY at DP. The id, the lane, the row, the scale and both payload fields (spread_ranks: 60, spread_ruin: 2) are byte-identical across the whole rebuild. Underneath it, battle.gd's read site moved 7,225 lines (:6783 to :14008, measured at DP itself rather than against HEAD) and changed which unit it reads from. A diff of the talent trees — the obvious instrument, and the one this audit reached for first — would have filed oc_spread as a documentation edit. What found it was diffing the READ SITE, and what found the Standing Vow beside it was diffing the enclosing GUARD CHAIN, because that read line never changed at all.

§3 — WHAT THE DOCUMENTS SAY, AND THE LADDER THAT HAS NOW BEEN WRONG FOUR TIMES

THE EQUIP-SLOT COUNT IS THREE, FLAT, FROM RUN START, AND IT DOES NOT GROW. Established here from the code and not from any document: Run.rune_slots() returns a literal 3. Its only other arm is RICH_SLOTS = 4, reached only when sim_run is true AND DOD_SIM_RUNE_ECON=rich is set in the environment — a sim lever whose own comment reads "every slot open from tier 1". That is a flat 4, not a ladder, and it is unreachable in a played run.

master.html HAS NEVER CARRIED THE GROWTH LADDER, AND THIS IS THE FOURTH BRIEF TO SAY IT DOES. Swept on UNWRAPPED text, which is the method EI had to invent for exactly this document: the file says "Three equip slots, flat, from run start — no growth ladder" at line 2444, and four further mentions all agree with it — "heroes begin with no runes and three empty slots" (line 32), "three rune slots (filled or empty)" (351–52), "Heroes begin the run with no runes and three empty slots" (2448) and "a read-only rune list (three flat slots)" (2714). Five sites, of which a line-anchored grep sees only THREE — one is broken by inline <b> tags and one wraps mid-phrase. Zero hits for "Equip slots", for "2 → 3 → 4", and for "starts the run choosing a rune". NO CORRECTION IS OWED AND NONE WAS MADE.

THE LINEAGE IS NOW FOUR DEEP AND THE REFUTATION HAS BEEN IN THE SOURCE SINCE CT. CT was told the ladder existed and caught it; EG's brief asserted it eleven batches later; EH's brief blamed master.html; EJ's brief quoted two contradictory descriptions as both live in a document that carries only one. battle.gd:23066–67 has read "Batch AN §9 deleted the rune ladder outright and rune_slots() has been flat 3 ever since" the whole time — and that comment WRAPS, so a line-anchored grep for it returns nothing. The refutation has been as hard to find as the claim.

AND THE CONFUSION HAS A SOURCE WORTH NAMING, BECAUSE IT WILL CAUSE A FIFTH. There IS a live growth ladder in this part of the game: the ITEM pouch, ITEM_SLOTS_BY_ZONE, which grows by zone and announces itself on the zone-boss card. docs/design-notes.md sets the two side by side under the heading "Why the ladder is the pouch's shape and not the runes'" — AN deleted the rune ladder because a run that dies in zone 2 never owns the last slot and an empty rune slot is dead weight; CT kept the pouch ladder because a pouch slot is filled the moment you reach a merchant. Two ladders, one deleted and one kept, one paragraph apart.

WHAT THE DOCUMENTS DO SAY ABOUT THE SYSTEM — AND IT IS THE OLD RULE, STATED AS CURRENT. master.html: "Each set is built to one rule: one rune per talent lane, plus one splash that carries a term from every lane", and "Rare alters an existing ability's numbers or grants a talent-like effect (talent-counter runes STACK with the talent)", and "The per-lane rule is what makes a rune a build decision rather than a power increment." All three are accurate descriptions of the code as it stands. The charter contradicts them, which is a decision rather than a defect, and is why nothing on this page corrects a document.

§4 — HOW BIG IT IS

MECHANICALLY IT IS A RE-KEY, AND IT HAS A SHIPPED PRECEDENT

Of the 59 talent clauses, 56 ride something the charter permits anyway. The node's effect already attaches to a spec passive, a stat, a protected core or a draft card at the read site; what makes the clause talent-keyed is only that the rune and the node write the SAME FIELD. Severing them is a second field read at the same line.

What the node's effect rides onClausesWhat a re-key costs there
A spec PASSIVE (Ruin, Burn, Chill, Resonance, Pack Bond, Poison, Break, Blood Frenzy, Seasoned Fighter)31 A rune_ field beside the node's, summed at the existing site. Data plus one line each.
A STAT or RESOURCE (Focus conversion, Mercy, Faith release, Break-damage cut, resource on a kill)15 The same, and several could simply be re-pointed at an existing general stat instead.
A PROTECTED CORE ability (Divine Shield, Consecrated Ground, Guard Change, Quick Shot)8 Cheapest of all — apply_payload's {"ability": …, "add"/"set": …} branch already does this with no new mechanics, which is the shape DO itself chose for 25 cells.
A DRAFT ability (the Survivalist's traps)2 Permitted by the charter as written; a field of its own at the same site.
THE NODE AND NOTHING ELSE3 These need an effect INVENTED, not moved. divine_presence_pct (Divine Presence), entropy_ranks (Entropy) and pleasure_pct (Pleasure from Pain) are per-turn drips that exist only as their node — there is no core ability, passive or stat underneath them to re-point at.

BATCH AL ALREADY DID THIS THREE TIMES, FOR THE SAME REASON. rune_grudge_bonus, rune_vigil_bonus and rune_on_edge_ranks are rune terms split out of a node's counter and read beside it, and the source comments carry both the method and the reason: "it used to add a rank to this counter, and re-pricing the node from 6% to 25% would have quadrupled the rune's number without anyone touching the rune." The On the Edge split also records the one non-obvious rule — "a threshold cannot be summed the way a magnitude can (35 + 25 = 60% is not both effects, it is a third effect neither one asked for). THE THRESHOLD TAKES THE MAX; THE PAYOUT SUMS." Any re-key that sums a threshold instead of maxing it will ship a magnitude nobody authored.

AND THE COUPLING IS ADDITIVE, NEVER CONDITIONAL, WHICH IS THE FACT THAT MAKES THIS TRACTABLE AT ALL. Derived rather than assumed: no rune payload in the file carries a condition or a has_node gate, and every one of the 59 talent clauses rides a node in the equipping hero's OWN spec tree — zero cross-spec. There is no rune anywhere that is dead without a talent, and none that reaches into another spec's tree.

THE COST THAT IS NOT THE CODE, AND IT IS THE LARGER ONE

36 of the 48 spec runes carry a lane field and are lane runes; the other 12 are the splashes. The lane runes hold 36 of the 59 talent clauses and the splashes hold 23. The authoring rule is what they were built on, and both design documents state it as current: one rune per lane, writing that lane's own counters, "worth taking precisely because it is off-build, and worth less to the player already deep in that lane."

Re-key them and that asymmetry is gone. A rune with its own field is worth the same to every hero of that spec, which is the definition of the power increment the rule exists to prevent. The splash runes lose more than the lane runes do: a splash "carries a term from every lane and pays for reaching outside one", and with no lanes to reach across it is a bundle of three unrelated numbers. 16 of the 65 runes are WHOLLY talent-keyed — every clause they own writes a counter — so those are not trimmed by the charter, they are emptied and must be re-authored from nothing:

Boiling Blood, the Bared Guard, the Bitter Grip, the Deep Bond, the Deep Sight, the Deepening Ruin, the Long Hunt, the Long Winter, the Open Hand, the Resonant Core, the Shared Wild, the Standing Vow, the Turning Pack, the Warded Robes, the Weeping Wound, the Whispering Dark.

THE HONEST ANSWER, NOT SOFTENED

It is not a small batch and a document correction, and it is not a rewrite of the rune layer either. It is a re-key of 59 clauses in 32 runes, of which 3 need new mechanics and 16 runes need new concepts — and a deliberate abandonment of the authoring rule that 48 of the 65 were designed around.

The engineering is small and well-precedented. The design question is not. Nothing in the code decides whether a rune set with no relationship to the talent trees is better or worse than one built against them; what the code can say is that the current sets are built on that relationship deliberately, that both design documents say so, that the machinery to sever them already exists and has been used, and that the Warden's set would not move while the Beastmaster's would move almost entirely. The charter is worth taking or not taking on those terms, and this page exists so it can be decided before the work starts rather than halfway through.

§5 — WHAT IS DELIBERATELY NOT DONE

  • No rune is re-keyed, re-authored, retuned or retired, and no lane field is removed. The charter is ruled and not implemented; this page sizes it.
  • No document is corrected. §3 looked for master.html contradicting the code and found the opposite — the document is accurate, and it is the charter that disagrees with both.
  • The White Flame's middle clause stays inert. pyromaniac_ranks is the one rune field in the game that is written and read nowhere — Inferno Master's per-turn step stopped existing at AR. unit.gd already flags it, and inventing a read site is the guess AR §4 forbids. It is the 135th clause and it pays nothing today.
  • The six "→ Talent:" log lines on rune-only effects are not changed. Player-facing text, and this batch changes none.
  • No gate is added. A gate encodes a ruling and nothing here is ruled. The one property a future gate would want — that no rune writes a live node's counter — is derivable in about twenty lines from LANE_TREES and runes.json, and belongs in the batch that takes the charter.
  • No CLAUDE.md rule is added. Nothing is settled until this is read.
