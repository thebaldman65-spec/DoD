  • Correction — the Shieldwall v1 fossil is deleted. There have been two Shieldwalls.   • Shieldwall is now a Block STANCE. Shieldwall and Interpose were the same verb pointed in two directions — both granted charges, both fully negated attacks, one at the Warden and one at everyone else — and the self-directed half was the stronger. Interpose keeps the guaranteed charges. Shieldwall stops granting them and raises his Block chance instead: +25% for 2 turns (Perfect: 3). 25 Rage, 2.0 initiative, 2cd, self-cast — unchanged. A status chip reads "+25% Block" and his Heavy Plating passive chip folds the bonus into its live total, so the readout never lies while the stance holds.
  • The trade, which is the point: the bonus rides the Heavy Plating slice of the block roll, so every block Shieldwall buys is a Heavy Plating block — and Tenacity and Rally feed on Heavy Plating blocks specifically, which Shieldwall's charges never triggered. He trades hard denial for an engine. It is stated in the ability description, because a trade a player cannot see is not a trade.
  • Shield Mastery re-specced in place (wd_shieldwall, same id, so saved ranks migrate and nobody is refunded): "+1 Shieldwall charge per rank" became "+1 turn of stance per rank", 2 ranks.
  • Block-source labels follow the charges. Interpose is now the only source of guaranteed blocks, so a charge block logs "(Interpose)", not "(Shieldwall)", and the charge chip reads "IP3" instead of "SW3". The log stays honest about what produced a block, which matters because two talents key off that distinction.
  • Prevented-damage instrumentation: Shieldwall is no longer credited as its own mitigation site — the credit now belongs to the block roll, which was already instrumented and credits the blocker. Counted once, and not lost.

What changed is that the guard which handles it is sims only: real play had no resolution mechanism at all, so at the measured ~0.9% of battles a tester doing five runs had roughly a one-in-three chance of landing in a fight that cannot end, with force-quitting the application as the only exit — which costs the run and comes back as "it froze" rather than as an opinion.

A forfeit is not a defeat, and folding them together corrupts the chronicle the moment testers start using the exit. The summary's chronicle line grows a "Cycles abandoned" figure, shown only once there are any.

2026-08-03 — Batch Z: the alpha shell — glossary, orientation, run summary

  • Why: Batch Y made the map a decision surface; this batch makes the run legible — the other half of a rough playable alpha. A first-time tester had to absorb the initiative timeline, skill checks, Pressure/Break, seven damage schools, bleed buildup, five spec resources, lane-gated talents, runes, trophies, and relics with no explanation anywhere in the build — every tooltip explains a number, nothing explained a system. And a wipe reported two lines and a New Run button: twenty minutes of play, no record. A confused tester answers "what confused me," not "was it fun."
  • Stage 0 — Batch Y reconciliation: checked before writing any map code. All of Y's stage-4 legibility items were present and live: rest/shop/event tooltips, the "Tier N of 10 — the <boss> waits" ladder readout, gold roads out of the current node, and the three-state visited/reachable/unreachable reads. Nothing was re-implemented; this batch only ADDED a Glossary entry to the existing map burger and the framing card. No duplicate tier readouts or tooltip paths exist.
  • The glossary (stage 1): data/glossary.json + scripts/glossary.gd (the Enemies/Events/Relics/Runes pattern — adding an entry is a JSON edit). 66 entries across seven categories: combat flow (initiative, skill check, Pressure & Break, crit/miss/parry, fallen heroes), all 25 debuffs the battle code can apply plus Quick Draw, the seven damage schools + resists, all nine resources (Rage, Mana, Resonance, Mercy, Empower, Faith, Focus, Loyalty, Ruin), progression (lanes, the ceil(N/3) curve, points, trophies, node scaling), gear (runes, scarred runes, relics-vs-runes — its own entry, the most confusable distinction in the game), and the run itself. Every entry was written from the code, with numbers verified at the read sites, not from the master doc (see the drift list below). The panel (scripts/glossary_panel.gd) opens from the map burger, the Party screen, and the battle burger; a category tree on the left, entry text with cross-links on the right. In battle it is pure Control UI — no awaits, nothing that touches the timeline — and the battle scene gates its raw _input while the panel is open so a click cannot grade a live skill check through the overlay. Contextual hooks: status chips now append their glossary one-liner to their tooltip when it adds information. Ability-tooltip and resource-bar hooks were considered and deferred (the chip hook is the high-value one; the stage was already large).
  • First-run orientation (stage 2): two things, neither a tutorial. (1) A skippable framing card on the first map of a first run — what a run is, boss → descend → three zones, death ends the run, bosses leave permanent relics. (2) A one-time pointer at the skill check when the first battle's first timing bar would appear — the marker, the gold/green windows, and the multipliers (+15%/+25% Break on Perfect, 60%/ half Break on Sloppy), because a tester who never notices the timing window is playing a materially worse game and will report it as shallow. Both are gated on Profile flags (new flags bucket + flag/set_flag), set on dismissal so a returning tester is never re-taught. Sims and autoplay cannot trip either: the card lives in the map scene (RunSim never loads scenes) behind a sim_run guard, and the pointer requires not sim and not autoplay and Run.active — verified by test.
  • The run summary (stage 3): both end panels — defeat and completion — replaced by a real summary screen: outcome and depth ("Wiped — Zone 2 (The Scarlands), Tier 6 of 10"), the final battle's type/theme/lineup and who fell, each hero's spec with talent count, lane spread, runes, and trophies, damage share across the whole run, the run economy (battles won, elites taken, gold earned/spent/unspent, rests, events), relics carried, and a chronicle line (cycles survived / lost) so a session of runs accumulates into something visible. A Copy summary button puts a plain-text version on the clipboard — every wipe becomes a report a tester can paste straight back, feedback data with no telemetry built. Plumbing, both the easy-to-get-wrong pieces done as specified: the summary snapshots the run state BEFORE clear_save() (the save logic was NOT reordered — a dead-but-resumable run is a worse bug than a missing summary), and the new run ledger lives on Run (Run.tally, save v4, tolerant load), banked from a battle-local slice at battle end because the battle scene reloads between fights. _stat writes the real-play slice only when sim is false, so RunSim's stats path is untouched and nothing double-counts. Ledger bump sites: battles/elites and damage (battle end, real runs only), combat gold (award_gold), shop spend, rests.

The load-bearing machinery held: the timeline formula, the skill-check windows and multipliers, Break, crit/miss/parry, the seven-school resist pipeline and its 85%/1-damage clamps, all nine resources, the talent gates (both models, correctly distinguished), and the run structure all matched the code exactly.
