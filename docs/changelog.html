2026-07-26 — Batch 37: Zone rotation — authored slot pools behind a flag

  • Zone identity is a first-class def now: ZONE_DEFS maps each zone to its display name, its boss kind, and a roster id per slot it can host — the Forest of Old fields roster 1 as the opener and the tougher roster 3 as the finale. The enemies.json "zones" tags officially mean ROSTER ids (they travel with the zone, never with run position); the boss is resolved from the zone def, replacing the old slot-keyed check.
  • Authored slot pools, not a flat pool: SLOT_POOLS lists candidates per position; a run draws one zone per slot. Random draws sit behind DOD_ZONE_ROTATION=1 and the default remains the fixed order — with today's single-candidate pools both modes draw identically, exactly the "build behind a flag until the pool fills" plan. The drawn sequence persists in the save (pre-rotation saves rebuild the fixed order); the victory screen's "Descend into..." button reads the actual next draw.
  • The 11-tier invariant is documented where it bites: talent income (~35 points/run) assumes 3 zones × 11 tiers; every zone shares the same FLOORS ladder, and a future zone that wants a different length forces a cost-curve revisit first.
  • What this batch does NOT do: author new zones. Slot 1 and 3 want second candidates (an opener and a true finale) before the flag flips on — that is design + art work, and the recipe is now four data touches (zone def, slot candidacy, roster tags, background art keys) with zero formula edits.
