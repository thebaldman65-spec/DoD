## Scope and snapshot

- **The line numbers are HEAD's**: commit `11ef9fa` ("Batch IQ"); `scripts/battle.gd` is 31,174 lines. Copies are in `scratchpad/snap1b/head/`.
- **The working tree changed while I worked.** At 15:31 `battle.gd` grew to 31,208 lines, and `classes.gd`, `run_state.gd`, `map_screen.gd` and `run_sim.gd` changed too. These are uncommitted Batch IR edits; the in-flight section at the end describes them. I edited nothing.
- **What a "pick" means here.** A pick chooses one body, or a subset, out of a pool. A walk pays every member, and a door test asks whether *any* member qualifies.
- **Companion facts the verdicts rest on, at HEAD.**
  - `heroes` never holds a companion. `_hero_side()` = living heroes + living companions (`scripts/battle.gd` `_hero_side`: `func _hero_side() -> Array:` to `return side`).
  - A companion is built with `is_hero: true` and `"abilities": []` (`_do_summon`: `"constitution": hunter.constitution, "abilities": []}` (its file read from the text around it)), `is_companion = true` (`_do_summon`: `comp.is_companion = true` (its file read from the text around it)) and `next_time = INF` (`_do_summon`: `comp.next_time = INF  # never drawn a turn from the timeline` (its file read from the text around it)).
  - `_next_unit` walks `heroes + enemies` (`_next_unit`: `var alive := (heroes + enemies).filter(func(u): return not u.dead)` (its file read from the text around it)), so a companion never acts and is never `attacker` in `_resolve`.
  - The hero-only callbacks are wired by `for h in heroes` at spawn: `shield_absorbed_cb` `_spawn_units`: `h.shield_absorbed_cb = _on_shield_absorbed` (its file read from the text around it), `vigil_cb` `_spawn_units`: `h.vigil_cb = _on_vigil_heal` (its file read from the text around it), `vow_cb` `_spawn_units`: `h.vow_cb = _on_vow_share` (its file read from the text around it), `rite_cb` `_spawn_units`: `h.rite_cb = _on_rite_return` (its file read from the text around it).
