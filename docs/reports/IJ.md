## §2 — CONVERTED, AND REPAIRED

### §2a — THE RESOLVER, AND THE DOORS

`Classes.resolve_figures(text, fields)` replaces a token with a value: `{=Battle.VESPERS_PCT*100}` reads a constant of a game script
(`Classes.FIGURE_SOURCES`: Ability, Battle, Classes, Relics, Run, Runes, Talents, Unit) times an optional scale; `{=@damage}` reads a
field of the entry the text belongs to, a dotted path walking dicts and arrays; `{=@damage*Ability.GRADE_DMG_MULT.perfect}` is one
reference times another. A value prints whole if whole, else to two places. **A token that names nothing stays visible and
`push_error`s** — it cannot pass silently. **It is applied at six doors and nowhere else**: `Ability.make` (a card's words and
Perfect), `Runes._load`, `Glossary._load`, `Classes.engine_desc` (a core rune's rule), `Talents.desc_for` and `Relics.desc_of` (new,
and every relic surface reads it: the unlock card, the relic screen, the draft screen's relic tooltips). A code-held table — the
status chips, the potions — formats its figure inside its `const`, which GDScript evaluates at compile time. **The strike's grade
multipliers were two literal tables in `battle._resolve`**; they are `Ability.GRADE_DMG_MULT` and `GRADE_BD_MULT` now, and the strike,
every Perfect token and the skill-check hint read them.

> ## THE QUESTION
> For each string in your slice: **does it state a FACT THE CODE DECIDES, and if it states it as a typed literal, does the
> code agree today?** The batch then (a) converts literals that have a constant to read so they format from it, (b) repairs
> every disagreement, and (c) pins the rest a player acts on. Your verdicts drive all three, so be exact.
>
> **A FACT THE CODE DECIDES** is any of:
> - **MAG** — a magnitude: a number, a percentage, a multiplier (*double*, *half*, *a quarter*, *x2.5*), a cap or floor.
> - **DUR** — a duration or count of turns (*for 3 turns*, *next turn*, *battle-long*).
> - **COND** — a condition: when/if it fires (*below 50% health*, *on a crit*, *while no Cleric stands*, *once a fight*).
> - **SRC** — a source: where something comes from or who offers it (*from elites and the Peddler*, *the zone boss*).
> - **SCOPE** — who it reaches (*every hero*, *allies*, *the Mage and the Cleric*, *each enemy*, *the caster*).
> - **COUNT** — a count of things (*three slots*, *one of each*, *two stacks*, *up to 4 presses*).
> - **NAME** — it names another game thing the code ties it to (a card, a status, a rune, an engine: *Guard Change swaps*,
>   *until Ice Lance releases it*). A name is a fact only where the code makes the tie.
>
> A string can state several facts. A string that states none is **NOFACT**, one of: **FLAVOUR** (a mechanically empty clause:
> *Coin is coin.*), **INSTRUCTION** (*Space to continue*, *Decide, then confirm.*), **LABEL** (a heading, a button word, a bare
> name, a section title, a stat name with no figure).
>
> **NOT PLAYER-FACING** — a string no player ever sees: a dictionary key or identifier, a `why`/reason column only code reads,
> a sim/console/readout print, a `push_error` for the developer, a node name, a resource path. Say why, per group.
> **DEBUG** — shown only behind the debug gate (`Run.debug_enabled()`, the map burger's debug items, the battle's DEBUG menu,
> `DOD_*` env flags): count them as player-facing **under DEBUG**, verify them like any other, and keep them apart.
>
> ## READS OR LITERAL
> - **READS** — the fact's figure or name is filled at runtime from the source: a `%d`/`%s` argument that is a constant, a
>   payload/field value, a variable the code computes, a name read off data (`ab.display_name`, a rune's `name`). Example:
>   Boil Over's description is formatted from `BOIL_OVER_PCT_PER_RAGE`; Sanctity's rule text from
>   `BattleUnit.SANCTITY_PER_STEP` (`Classes.engine_desc`); a chip's words read off the rune payload (HZ §1d's rule,
>   `battle._refresh_rune_chips`); the vow's name read off the rune data (`_vow_name()`).

>   `{chp:N}` / `{tot:N|stat}` is LITERAL for its N** (`Classes.resolve_values` computes only the parenthetical from it).
>   A `%d` whose argument is itself a typed number in the same call (`"+%d%%" % 30`) is LITERAL.
> - A string can be **MIXED**: some facts read, some literal. List it as MIXED and give a FACTS row for each literal fact.
